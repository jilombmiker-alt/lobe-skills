# 三轮对话框架

## 总原则

每一轮只回答一个层级的问题，并在指定输出结束后停止。下一轮以用户明确确认或“继续拆解”触发。每轮都沿用同一证据编号和三种证据等级。

| 轮次 | 核心问题 | 输入重心 | 主要输出 | 明确不做 |
|---|---|---|---|---|
| 1. 用户旅程 | 用户实际经历了什么？ | 聊天、按钮、表单、画布、资产、错误、预览 | 证据表、三泳道旅程、痛点 | Agent 内部实现、Prompt、工具推测 |
| 2. Agent 契约 | 哪些 Agent 实际出现，怎样协作？ | Agent 回复、交接、资产变化、任务/状态 | I/O 卡、工具表、字段表、数据流 | 完整 System Prompt |
| 3. 功能等价 Prompt | 一个目标 Agent 如何在同样边界下工作？ | 该 Agent 的全部可见记录和第二轮契约 | 状态机、规则、Prompt、测试 | 声称还原官方 Prompt；拆其他 Agent |

## 轮次衔接

1. 第一轮把“用户看见什么、能做什么、实际产物何在”固定为证据账本。
2. 第二轮把同一账本重新按“谁读、谁判断、谁写、谁交接”组织，暴露状态与资产断点。
3. 第三轮从单 Agent 契约中提取最低必要规则；未证实的规则保持未知，工程稳定性规则标为建议。
4. 测试集将 Prompt 再反向检验到第一轮的证据标准：不能因自然语言成功就跳过资产和状态核验。

## 标准收尾语义

- 第一轮：等待用户确认旅程与证据边界。
- 第二轮：等待用户选定一个 Agent。
- 第三轮：等待用户检查该 Agent 的输入、输出、工具与全局上下文是否正确。

不要在任意收尾时自动开始下一层分析。
