# 输出模板

## 1. 用户旅程证据表

| 阶段 | 用户目标 | 用户动作 | 页面反馈 | 用户决定 | 页面/资产变化 | 阻力 | 证据 |
|---|---|---|---|---|---|---|---|

证据栏写：截图编号、页面原文、按钮名、Agent 名、可见资产和错误信息。每个结论内嵌【页面事实】【合理推断】【尚未确认】。

三泳道图只保留：用户、产品界面、系统结果。菱形判断门写明确条件，如“满意 / 不满意”“生成成功 / 失败”“继续 / 中断”“余额充足 / 不足”。没有页面证据的分支用虚线并标“尚未确认”。

## 2. Agent I/O 契约卡

```text
Agent：名称
1. 核心目标
2. 触发条件
3. 输入信息
   - 用户当前输入：
   - 用户长期信息：
   - 项目全局上下文：
   - 上游 Agent 输出：
   - 平台公共资产：
   - 工具或运行时结果：
4. 可观察判断
5. 调用工具（功能命名，非官方工具名）
6. 输出信息
   - 用户回复 / 页面组件 / 结构化字段 / 视觉或音视频资产 / 状态 / 下游任务
7. 全局上下文读写
   | 字段或对象 | 读/写 | 生产者 | 消费者 | 更新时机 | 证据等级 | 证据 |
8. 完成条件
9. 异常与重试
10. 尚未确认的问题
```

工具表：

| 功能性工具名 | Agent | 触发/前置 | 结果状态 | 不可断言的内容 | 证据 |
|---|---|---|---|---|---|

结果状态限用：`页面结果确认`、`用户可见摘要/计划`、`入口可见`、`尚未确认`。

## 3. 功能等价 System Prompt 骨架

```text
Agent名称

1. 角色
2. 核心目标
3. 任务边界
4. 输入契约
5. 全局上下文协议
6. 工作流程
7. 工具调用规范
8. 用户确认机制
9. 结果验证
10. 修改与回退
11. 异常处理
12. 状态机
13. 下游交接
14. 完成条件
15. 输出格式
```

写作规则：

- 页面出现的名称、按钮和字段优先原样使用。
- 未公开的字段写成语义占位字段，例如 `project_brief_draft`，并说明“推导设计，非官方字段名”。
- 未公开的工具写成 `<创建项目计划草案>`，并说明“功能性名称，非官方工具名”。
- Prompt 的稳定性增强规则（状态读回、幂等、版本、失败、取消）必须标注为【建议规则】，而非原产品事实。
- 完成条件不得仅依赖 Agent 的自然语言；至少要求资产/状态存在、上下文写入成功、结果验证通过、用户确认记录和交接包完整（只对目标 Agent 范围内的项目适用）。

## 4. 规则—证据追溯表

| Prompt 规则 | 分类 | 页面证据 / 推导依据 | 限制 |
|---|---|---|---|

分类只能使用：【事实规则】【推断规则】【建议规则】【未知】。

## 5. 最小测试集

| 测试 | 测试输入 | 初始状态 | 预期判断 | 预期工具调用 | 预期状态变化 | 不允许出现的行为 |
|---|---|---|---|---|---|---|

至少包含：正常输入完整、缺少必要输入、局部修改、工具失败、用户中断、全局上下文与页面状态冲突。
